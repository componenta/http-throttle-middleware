# Componenta HTTP Throttle Middleware

PSR-15 промежуточный обработчик для ограничения частоты запросов с фиксированным окном. Он ограничивает количество запросов на ключ, добавляет заголовки лимита к успешным ответам или возвращает `429 Too Many Requests`.

Используйте пакет, когда HTTP-конвейеру нужен простой лимит запросов по IP клиента, id пользователя, API-ключу или другому ключу приложения.

## Граница пакета

Пакет только ограничивает частоту запросов. Он не аутентифицирует пользователей, не разбирает заголовки доверенного прокси и не предоставляет глобальный провайдер конфигурации. Если приложение работает за прокси, поставьте `componenta/http-trusted-proxy-middleware` перед этим обработчиком, чтобы был доступен атрибут запроса `client_ip`.

## Установка

```bash
composer require componenta/http-throttle-middleware
```

У пакета нет провайдера конфигурации. Зарегистрируйте лимитер и промежуточный обработчик явно.

## Лимитеры

| Класс | Хранилище |
|---|---|
| `CacheRateLimiter` | PSR-16 кеш. |
| `FileRateLimiter` | Директория файловой системы. |

Оба реализуют `RateLimiterInterface::hit(string $key, int $limit, int $window): RateLimitResult`.

`CacheRateLimiter` использует переносимые 64-символьные хешированные ключи PSR-16. Это приблизительный ограничитель: PSR-16 не гарантирует атомарность чтения и записи, поэтому при конкуренции квота может быть превышена. Для строгой защиты используйте атомарное хранилище.

`FileRateLimiter` использует постоянные блокировки сегментов и атомарную замену файлов в приватной локальной директории. Просроченные записи удаляются по сохранённому времени истечения. Хранилище должно поддерживать корректные `flock()` и `rename()`. Ошибка записи или блокировки приводит к исключению, а не к разрешению запроса.

`RateLimitResult` содержит:

| Свойство | Значение |
|---|---|
| `allowed` | Можно ли продолжить обработку запроса. |
| `limit` | Максимум запросов в текущем окне. |
| `remaining` | Остаток запросов в текущем окне. |
| `retryAfter` | Сколько секунд осталось до сброса окна. |

## Промежуточный обработчик

```php
use Componenta\Http\Middleware\Throttle\ThrottleMiddleware;

$middleware = new ThrottleMiddleware(
    limiter: $limiter,
    responseFactory: $responseFactory,
    limit: 60,
    window: 60,
);
```

По умолчанию ключ берется из атрибута запроса `client_ip` или из `REMOTE_ADDR`. Пользовательский резолвер ключа может использовать id пользователя, API-ключ или другой идентификатор.

Переопределения для маршрута можно передать через атрибут запроса `rate_limit` с положительными целочисленными `limit` и `window` и необязательным непустым идентификатором политики `policy`. Для независимых квот маршрутов задавайте разные идентификаторы.

```php
$request = $request->withAttribute(ThrottleMiddleware::ATTR_RATE_LIMIT, [
    'policy' => 'login',
    'limit' => 10,
    'window' => 60,
]);
```

Успешные ответы получают заголовки `X-RateLimit-Limit` и `X-RateLimit-Remaining`. Отклоненный ответ получает статус `429`, тело `429 Too Many Requests` и заголовки `Retry-After`, `X-RateLimit-Limit`, `X-RateLimit-Remaining: 0`.

## Миграция

Новый формат файлов и ключей кеша сбрасывает старые квоты. Обновляйте процессы приложения согласованно; прежние файлы необходимо удалить отдельно. Ошибки `RateLimitStorageException` обрабатываются на уровне приложения. Заголовки `X-RateLimit-*` являются историческими нестандартными полями. Ответ 429 содержит `Cache-Control: no-store`.

Для запуска тестов: `composer test`.

Необязательный параметр конструктора `policy:` изолирует независимые экземпляры middleware с общим хранилищем и одинаковыми настройками квоты. Идентификатор политики маршрута учитывается внутри этого пространства. Функция определения ключа должна возвращать непустую строку. IPv4 и соответствующий IPv4-mapped IPv6 используют одну квоту.

## Обслуживание файлового хранилища

Периодически вызывайте `$limiter->collectExpired()` в отдельном процессе или задаче CLI. Метод возвращает число удалённых просроченных записей, очищает оставшиеся временные файлы, сохраняет постоянные файлы блокировок и пропускает занятые записи. В `hit()` автоматического сканирования нет. Относительный путь к хранилищу разрешается один раз в конструкторе. Контролируйте свободное место с учётом количества уникальных ключей. Не помещайте персональные заголовки квоты в общий кеш; ограничитель должен выполняться до попадания в кеш, если такой запрос должен расходовать квоту.
